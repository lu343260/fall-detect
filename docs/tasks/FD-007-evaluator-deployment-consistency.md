## 任务背景

FD-002 已完成场景评估框架和初版自动评估入口 `evaluate_scenario_set.py`。代码审查发现，评估器虽然复用了 `ONNXPoseDetector` 和 `FallDetector`，但在输入方向、跳帧、状态机调用、无效帧和时间语义方面与正式摄像头部署流程不完全一致，不能直接作为严格部署等价评估工具。

## 目标

在不修改 YOLO 模型、不修改 `FallDetector` 核心判断逻辑、不改变现有部署流程的前提下，使离线评估器具备明确、可审计的部署一致性模式，并区分：

- **media_time 模式**：按视频时间轴进行可复现的离线指标评估；
- **realtime 模式**：尽可能复刻正式摄像头循环的帧处理、跳帧和状态机更新时间语义。

## 当前问题

- 图像旋转逻辑不一致：正式入口会旋转 180°，评估器当前直接使用原始帧。
- `FRAME_SKIP` 行为不一致：评估器没有复刻正式入口的跳帧处理。
- `FallDetector` 调用频率不一致：正式入口按固定帧条件调用，评估器当前对每帧有效关键点调用。
- 无效关键点处理不一致：评估器可能把无效帧当成 `fall=False`，从而错误触发恢复判断。
- 时间统计模式不明确：评估器使用视频名义时间，正式入口使用 `time.monotonic()`。
- 256 模型预处理路径不一致：评估器通过隐式修改推理模块全局变量适配输入尺寸，和正式入口的调用路径不同。
- 标签缺失处理不足：缺少事件标签的样本可能被静默当成非跌倒样本。
- 恢复时间定义不严格：当前使用 `fall=True → fall=False` 推断恢复，没有严格绑定状态转换。

## 分阶段实施

### Phase 1：修复高影响一致性问题

- 对输入帧复刻正式入口的图像旋转逻辑；
- 增加并复刻 `FRAME_SKIP` 行为；
- 按正式入口的条件保持 `FallDetector` 更新频率一致；
- 无人体、关键点不足或推理无效时保持上一有效状态，不触发假恢复。

### Phase 2：优化评估接口

- 显式配置并记录模型输入尺寸，确保预处理、模型输入和后处理语义一致；
- 删除通过修改 `onnx_inference` 模块全局变量实现的隐式适配；
- 检查 `manifest.csv` 与 `events.csv` 的样本覆盖，标签缺失时标记为 `INVALID` 并输出原因。

### Phase 3：完善指标

- 以明确的 `FALLING/ON_GROUND → NORMAL` 状态转换定义恢复时间；
- 增加 `media_time` 和 `realtime` 模式，并在报告中记录实际模式；
- 区分离线可复现的报警延迟与真实部署中的端到端响应时间。

## 修改范围

- 允许修改：`evaluate_scenario_set.py` 及其测试文档、运行记录格式。
- 允许生成：部署一致性检查结果、逐帧/逐视频预测记录和指标报告。
- 不在范围：修改 YOLO 模型、修改 `FallDetector` 核心逻辑、改变正式摄像头/龙芯部署入口、进行模型或算子性能优化。

## 验收标准

- [ ] 评估器在相同输入帧、旋转、`FRAME_SKIP` 和状态机更新条件下，与正式入口使用一致的处理规则。
- [ ] 无效关键点帧不会改变有效状态，也不会被记录为恢复事件。
- [ ] 输入尺寸、预处理路径、模型路径和运行模式均显式记录，且不依赖隐式模块全局变量修改。
- [ ] 缺失或不完整标签会被标记为 `INVALID`，不会静默计入 TN、TP、FP 或 FN。
- [ ] 恢复时间仅由明确的状态转换计算，并能区分 `media_time` 与 `realtime`。
- [ ] 使用固定样本和配置运行后，输出逐视频结果、逐帧记录及可审计汇总报告。
