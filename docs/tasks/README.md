# 自动化研发流水线 v1.0 任务管理

当前任务调度索引见 [`任务索引.md`](./任务索引.md)。本 README 保留为任务管理规则和历史入口。

本目录是 AI-Fall-Detection-System 下一阶段的任务池。任务来源于项目根目录 `AGENTS.md`、`docs/development/当前项目状态报告.md`、`docs/benchmarks/performance_baseline.md` 和现有 AI 协作目标。

## 使用规则

- 每个任务使用唯一 ID：`FD-<编号>`，编号只递增，不复用。
- 任务状态统一使用：`READY`、`RUNNING`、`BLOCKED`、`COMPLETED`、`CANCELLED`。定义和当前调度信息见 [`任务索引.md`](./任务索引.md)。
- 开始任务前，先补充执行日期、当前 commit、平台和依赖的实验输入。
- 任务只允许修改“修改范围”中列出的内容；实验视频、图片、模型和 benchmark 产物默认保留在版本库外或按项目约定归档。
- 验收时必须逐条对照“验收标准”，并把结果写回任务文档或任务要求的目标文档。
- 完成任务后才允许提交 commit；一个任务原则上对应一个独立 commit，不混入无关改动。

## 推荐执行顺序

```text
FD-001 ─┬─> FD-004 ─┐
        └─> FD-002 ─┼─> FD-003
FD-002 ─────────────┘
FD-001 ───────────────> FD-005（仅龙芯实测阶段）
FD-001 + FD-002 ──────> FD-006
FD-002 ────────────────> FD-007
```

FD-001 和 FD-002 是证据基础；FD-003、FD-004、FD-006 应引用它们的结果，避免使用不同计时口径或无标签样本得出结论。FD-005 的 PC 架构设计可以先行，龙芯实测阶段再引用 FD-001/FD-004 的结果。

## 任务完成定义

任务必须同时满足：实现或实验产出完成、验收标准逐条通过、要求更新的文档已更新、commit 符合任务约束，并在任务文档中记录实际结果和未解决风险。
